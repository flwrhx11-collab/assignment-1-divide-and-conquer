# Assignment 1: Divide-and-Conquer Algorithm Analysis

## A. Project Overview
This project implements and analyzes four classic Divide-and-Conquer algorithms in Java:
- **MergeSort**: Sorting with auxiliary buffer and Insertion Sort cutoff.
- **QuickSort**: Randomized pivot selection and tail-recursion optimization.
- **Deterministic Select**: Median-of-Medians algorithm for $O(n)$ worst-case selection.
- **Closest Pair of Points**: Divide-and-conquer $O(n \log n)$ geometric algorithm.

## B. Algorithm Analysis

### 1. MergeSort
- **How it works**: Divides the array into two halves, recursively sorts them, and merges the sorted halves using an auxiliary array. Switches to Insertion Sort for subarrays of size $\le 15$.
- **Complexity**: Time $\Theta(n \log n)$, Space $O(n)$.
- **Recurrence**: $T(n) = 2T(n/2) + \Theta(n)$. By Master Theorem (Case 2: $a = 2, b = 2, f(n) = \Theta(n)$), $T(n) = \Theta(n \log n)$.

### 2. QuickSort
- **How it works**: Selects a random pivot, partitions the array in-place, and recurses on the smaller partition first while iterating over the larger partition to bound stack depth.
- **Complexity**: Average Time $O(n \log n)$, Worst-case Time $O(n^2)$, Auxiliary Space $O(\log n)$.
- **Recurrence**: Average $T(n) = 2T(n/2) + \Theta(n) \implies O(n \log n)$.

### 3. Deterministic Select (Median-of-Medians)
- **How it works**: Groups elements into 5s, finds medians of each group, recursively finds the median of medians as a pivot, partitions in-place, and recurses only into the target partition.
- **Complexity**: Worst-case Time $O(n)$, Space $O(\log n)$.
- **Recurrence**: $T(n) \le T(n/5) + T(7n/10) + O(n)$. By Akra-Bazzi intuition, since $1/5 + 7/10 = 9/10 < 1$, the linear work $O(n)$ dominates, guaranteeing $T(n) = O(n)$.

### 4. Closest Pair of Points
- **How it works**: Sorts points by x-coordinate, recursively finds the minimum distance in left and right halves, constructs a 1D strip of width $2d$ around the dividing line, sorts by y-coordinate during merge, and inspects points in y-order.
- **Complexity**: Time $\Theta(n \log n)$, Space $O(n)$.
- **Recurrence**: $T(n) = 2T(n/2) + O(n)$. By Master Theorem, $T(n) = \Theta(n \log n)$.

## D. Discussion
1. **Match with Theory**: Yes, empirical execution times align with $O(n \log n)$ for MergeSort, QuickSort, and ClosestPair, and $O(n)$ for Deterministic Select.
2. **Input Structure Effect**: QuickSort with randomized pivot handles sorted and reverse-sorted inputs efficiently, avoiding the $O(n^2)$ worst-case.
3. **Smaller-First Recursion**: Recursing on the smaller partition first bounds the call stack depth to $O(\log n)$, preventing `StackOverflowError`.
4. **Median-of-Medians Guarantee**: Grouping by 5 ensures that at least 30% of elements are smaller than and 30% are larger than the pivot, ensuring a balanced partition step ($7n/10$).
5. **Closest Pair Speedup**: Brute-force checks $O(n^2)$ pairs, whereas divide-and-conquer checks only a constant number of neighboring points in the strip (at most 7 points per element in y-order).
6. **Practical Factors**: JVM JIT compilation, CPU cache locality (sequential array access), and garbage collection overhead strongly affect microbenchmark performance.
